# 子任务三：部署优化与无人机飞行报警

本模块使用子任务一的真实郑州建筑/DEM，以及子任务二未实测标定的四类感知模型。提供一套可直接播放的计算示例和可重新运行的后台优化器。算法版本 `deployment-1.0`。

## 如何观看

启动页面后点击“部署与飞行”，默认载入已计算的增强方案。点击“播放飞行”，可看到无人机 D-01 从城区西侧经过河南博物院周边飞向东侧；红色连线表示当前模型帧实际检出的设备。支持暂停、1/10/30/60 倍速、进度拖动与回到起点。

报警区显示“已检出”“丢失确认中”或“未检出”。同时列出检出设备及模型裕量，记录首报、重新发现、连续两帧未检出后的失联确认、进入/离开核心区。不是按是否进入一个圆圈直接触发报警，而是逐台复用真实网格遮挡、视场、距离、噪声及链路判定。

轨迹起点已经位于模型城区，示例可能在 0 秒即产生首报。无人机图标为放大示意，感知计算仍使用目标参数中的实际尺寸/RCS/声压等。默认方案在这条离散飞行验证轨迹上持续检出，不会为了演示失联而伪造掉线。可选择经济方案或其他工况查看不同结果。

## 设备提示与实时告警

- 鼠标悬停地图中的部署设备点，显示设备类型、实际型号及编号；当前检出的设备显示红色脉冲和外圈提示，未检出设备保留原类型颜色。
- 地图右上角常驻目标 D-01 信息卡，实时显示 WGS84 经纬度、相对当前 DEM 表面的离地高度与模型高程；“定位无人机”将视角移到目标附近。目标旁的标签同步显示报警状态和离地高度。
- 点击信息卡中的“开启语音报警”启用中文播报，再次点击关闭。启用和开始/恢复播放时播报当前状态；播放中状态变化会播报，持续状态每 30 秒提醒，自动播报至少间隔 5 秒，不堆积历史语音。暂停、重置、跳转、重新计算或离开界面会取消尚未完成的播报。
- 语音使用浏览器 Speech Synthesis 和系统可用的中文声音，优先选择本地中文声音；需要浏览器支持且系统声音开启。浏览器不支持时按钮禁用，播放失败会显示提示。Mac 可在系统设置中安装中文朗读声音；语音不需要项目新增服务端接口。
- 离地高度直接在原始地形三角面上插值；模型高程由源 ENU/ECEF 变换还原，源 DEM 未注明垂直基准，不将该数值称作经标定的海拔。显示随平滑轨迹更新，设备检出仍按 2 秒模型帧判定。

| 经济 | 29 | 299.54 | 486/490 | 476/490 | 484/490 | 401/490 |

推荐方案包含 **45 台雷达、6 台无线电设备、4 台声学设备**。光电型号参与候选计算，但在当前目标尺寸、固定视场和相对成本假设下未被选中，不为凑齐类型强制购买无增益设备。光电窄视场不是全向覆盖，算法没有把云台转动范围冒充瞬时视场。

该方案检查 732 个设备/姿态候选、490 个有效自由空域点。基线、无线电静默、给定雨雾噪声工况下采样覆盖均为 100%；给定强电磁干扰下为 **97.96%**，仍有 **10 个**盲点，界面如实标红，不能称为所有工况都无死角。核心区在上述四工况下均覆盖当前采样。

**100% 只针对列出的有效采样点和给定模型条件，不是连续空域、全部楼缝、实际装备或全部威胁场景的覆盖保证。** 不具有数学全局最优证明。不能把未提供 DEM 的区域算作已覆盖。

## 范围、采样及盲区面积

默认范围为仓库建筑外包范围与有效 DEM 支持的自由空域；也可选河南博物院周边 2.4×2.4 km。核心区域水平半径默认 700 m、采样权重为外围的 3 倍。

默认网格间距 500 m，离地高度 30/60/100 m。地面高度来自 DEM，不等于屋顶高度。处在建筑实体内的目标采样被排除，并额外在核心区较高建筑的外缘设置近立面点。本例排除 204 次 DEM 空缺采样和 14 次建筑内部采样；这些排除项在报告与页面单独列明，没有计为成功覆盖。

绿色/红色点表示选中高度层及工况的覆盖/盲点。“盲区占比”是采样点比例。报告另提供各高度层仅对规则网格的近似面积：有效/盲区网格中心数 × 网格间距平方。边界、建筑和 DEM 空缺未做精确多边形裁剪，近立面额外点不用于外推面积，不能把不同高度层面积相加称作地面盲区面积。

500 m 网格用于快速方案筛选，不足以证明所有街巷无盲区。可调密网格重新计算，后台显示进度并允许取消；密集网格需要更多时间与内存。

## 候选点与优化方法

1. 依区域划分候选网格，提取实际建筑上的高、低屋顶代表点，要求有 DEM 支持且位置对应真实网格表面，默认安装在表面上方 2 m。
2. 设备候选包含 03D 雷达、TDOA-X1B、NVT-951 和 CRY8500。雷达比较 0/-15/-30° 模型安装俯仰姿态；残余盲点附近会进一步搜索可见的几何表面补点与定向姿态（最低 -60°）。实际天线/云台是否支持这些姿态，需要厂家和现场确认；当前仅按可调姿态模型计算。
3. 对每个候选及每个空域采样，使用建筑/地形 BVH 做遮挡求交，复用子任务二模型，分别在基线、静默、雨雾噪声、电磁干扰工况判定。只有数据支持充分、满足几何/信号门限且保留默认 3 dB 裕量时才计入规划覆盖。
4. 为候选集仍无法覆盖的位置增加邻近候选，不降低覆盖阈值。补点本身也要通过真实几何与各工况门限。
5. 在预算/设备数约束下，按“新覆盖权重 / 相对成本”贪心选点；删除冗余设备后再次利用释放预算补选，最多四轮。它是加权集合覆盖启发式，不是全局最优求解器。
6. 按经济、均衡、增强预算分别生成方案，复核所选设备组合的 EMC 代理损耗，重新计算最终覆盖。以加权盲点最少、再相对成本低、再安装代理指标低的顺序推荐。

相对设备成本默认为雷达 12、无线电 5、光电 4、声学 2，并叠加小的高度相关安装代理成本；全部为可调假设，**不是人民币报价**。屋顶承重、产权、供电和网络条件没有数据，不宣称已完成现场施工可行性确认。

EMC 使用近邻同频代理：两台雷达频率差 <0.1 GHz 且距离 <600 m 时叠加随距离变化的损耗；候选还采用示例频率分组。实际带宽、极化、发射时序、材料及互扰机制未标定，这不是实际电磁兼容认证。静默、雨雾和干扰工况是有限扰动校核，不等于已经证明多方向/蜂群等所有威胁鲁棒性。

## 飞行及报警时序

路线在有效 DEM 连通域上寻找西侧—核心区—东侧通路，再按约 20 m 间距加密。高度兼顾约 60 m 地形离地高度和建筑上方至少 25 m 的模型净空，通过前后坡度包络限制爬升/下降，并逐段复核源网格碰撞。它是城市数字模型中的演示路径，不是实际航空导航方案。

当前路径约 **7.54 km**，模拟速度 **15 m/s**，约 **8 分 23 秒**；默认 10× 播放。运动按三维弧长插值，报警按 **2 秒**模型帧更新，本例共 **253 帧**。规划使用额外 3 dB 余量，运行报警使用感知模型原始阈值。帧间短暂漏检不能从采样结果排除。

默认推荐方案的这条轨迹在 253 个模型帧均检出，首报为 0 秒、失联事件为 0。回放可跳转，跳回时重建报警状态，避免沿用“未来”的报警记录；播放跨过多个模型帧时会依次更新全部中间事件。报警没有外发消息或控制真实设备。

“部署方案”或“覆盖工况”改变后，会在 Worker 中重新计算该方案/工况的报警帧，计算完成前禁用播放，不会用旧设备的报警冒充新方案。后台计算可取消，保留上次完成的方案。参数错误不覆盖已完成结果。

## 与装备面板的关系

点击“到装备面板调整”可载入所选方案的设备、环境和当前无人机位置，继续使用上一任务的拖动/信号查询功能。装备上限扩展为 64 台；大于 12 台时仅绘制当前设备的标称范围阴影，所有设备点位仍保留。

部署示例是有版本和来源哈希的计算快照，手动修改装备面板不会自动篡改其历史覆盖率。点击“重新优化”采用当前目标特征和环境，再按本模块候选型号、位置/姿态与预算求解；四个工况各自定义发射状态和单目标数量。本模块没有把当前手动设备清单当作固定安装点约束。

## 重算、导出与验证

```bash
npm ci
npm run prepare:data
npm run plan:build
npm test
npm run build
```

`plan:build` 输出 `artifacts/deployment-report.json`，不覆盖已提交示例；`plan:example` 明确重新计算并更新 `public/deployment-example.json`。默认全城优化在本环境约数分钟，具体取决于资源。示例已预计算，查看和播放不需要等待这一步。

页面导出 JSON 包含设备坐标/参数、三套方案、工况与覆盖矩阵、近似面积、成本、地理原点/源文件哈希、路线、全部模型帧和当前回放报警记录。报告中的 ENU 需使用所附 ECEF 变换/城市基准进行 GIS 配准，不把本地米坐标当经纬度。

测试覆盖成本/设备上限、冗余删除后补选、不可行覆盖、不合法设置、EMC 代理、报警首报/确认丢失/重获、时间插值、来源一致性、覆盖率与矩阵一致性，并独立用真实网格射线复核部分覆盖/盲点及轨迹段。启动服务并安装本机 Chromium 后运行：

```bash
npm run test:planning:browser
```

浏览器测试验证实际方案加载、播放/暂停/回放/跳转、报警导出、后台工况计算、取消、无效参数、移动布局及设备面板联动。不能把这些软件测试当作实地设备验收或真实探测概率验证。
