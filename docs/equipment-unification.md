# 装备建模统一使用说明

本次在上游 `zzl2022/UAV` 的 `f684c3b9feac` 本地接入版本上整合，未执行上传或推送。顶部仅保留“装备建模”作为设备评估入口，原独立光电／声学面板不再挂载。原 Python 模型、配置和单元测试继续保留。

页面已移除依赖本机5180端口的独立查看器链接，分发后的主平台不需要该额外服务。原本机独立查看器可按其单独启动说明访问。

## 日常使用

1. 双击本机桌面的“UAV低空平台”。团队首次安装后可双击仓库根目录的“启动装备建模平台.cmd”。
2. 点击“装备建模”，在“当前装备”选择 NVT-951 光电或 CRY8500 声学。也可通过“添加”增加同型号设备。
3. 默认使用“比赛资料 · 基础评估”。地图设备球、目标球、坐标输入、选点和拖动均使用同一套场景状态。
4. 光电可选择可见光或热成像、工作焦距和朝向，设置目标宽高。点击“朝向当前目标”计算云台指向。
5. 如需演示视场内外判断，勾选“启用自定义视场试算（场景假设）”，填写水平和垂直角度。关闭时不注入演示视场。
6. 声学可切换30／70／110 cm阵列，查看标称距离条件与几何方位。110 cm阵列可勾选“核对目标频带”。
7. 在“光电／声学场景对比”填写场景名称并保存。移动目标或调整设置，等待评估完成后再次保存。
8. 导出“中文报告”供展示、打印或另存为PDF；导出“对比数据”供复核。记录仅保存在本次页面会话。

中文页面和报告只展示有有效结果的指标，保留有效的零值和“否”。未计算的字段不生成项目或占位文字。完整 JSON 保留空值及来源状态供程序判断，未计算不会变成零。

## 两种评估方式

| 方式 | 光电／声学计算 | 主要用途 |
| --- | --- | --- |
| 比赛资料 · 基础评估（默认） | Python 原模型和设备YAML，复用当前建筑／地形直达路径 | 核对资料条件、几何关系、通道、阵列、场景对比 |
| 假设参数 · 环境仿真 | 平台原 JavaScript 模型及可调整的环境和系数 | 分析环境变化趋势，展示像素、声压、信噪比和近似误差 |

雷达和无线电继续使用原有模型。基础评估不会用仿真结果填充计算不了的指标。服务失败时清除本次评估并禁止保存或导出当前方案，不回退到假设结果。

基础评估不绘制假设识别距离形成的光电／声学覆盖体。地图鼠标在这两类设备下查询空间距离和直达路径。原三维体场算法仅支持雷达和无线电，选择光电／声学时不列出体场操作。

## 参数和方法

- 光电配置：`equipment_models/optical/config/optical_nvt951.yaml`。
- 声学配置：`equipment_models/acoustic/config/acoustic_sensor.yaml`。
- 修改后点击“刷新设备资料”。Python每次评估重新读取YAML，导出的配置哈希可核对实际版本。
- 比赛资料包含光电通道分辨率、焦距范围、云台范围等；声学包含0.01～500 m标称距离、阵列规格和110 cm阵列的20 Hz～20 kHz频带等。
- 设备位置、目标位置、目标宽高、所选工作焦距及可选自定义视场属于仿真场景设置。
- 焦距驱动视场需要有效传感器宽高；资料中没有这些数据。默认不生成视场数值。用户设定的固定视场不随焦距改变；配置补充有效传感器尺寸后原模型可按焦距计算。
- 光电投影采用针孔近似与目标正对、轴向对齐假设。视场判断针对目标中心。机械转动范围与光学视场分别检查。
- 声学资料的94°×76°未确认为声学波束范围，基础评估不裁切声学方向；假设仿真的新建声学设备默认全向接收，并明确为假设。已有导入方案保留用户设置，方向范围仍可调整。
- 建筑遮挡不将声学能力置零。基础评估不凭标称距离生成实际探测结论。
- 资料基础模式不输入外部天气、光照、背景噪声或目标声级；真实检出率、识别率与定位精度没有标定依据。假设仿真也不代表实测精度。

## 场景数据与适用范围

场景沿用平台由官方建筑轮廓、`high` 字段和DEM生成的真实网格。浏览器使用既有 `createSceneQuery.trace` 查询，不另建GIS引擎。Python接收查询结果，校验原点及场景哈希，未独立重算网格。

Three.js坐标为 `[东, 上, -北]`，单位米；适配为原 Python 模型的 `[东, 北, 上]`。局部上坐标不等于离地高度或海拔。建筑高度字段语义、DEM垂直基准仍需核实；DEM空缺不能视为畅通。前端仅省略相应不可用指标，JSON保留条件状态。

任务三与部署模块继续使用原有 JavaScript 仿真链路，本次没有将资料基础结果替换为其优化评分。两种模式的用途在界面和导出字段中区分；任务三的演示结果仍属于假设条件下的仿真。

## 团队安装与启动

Node.js 22.12以上（推荐24）、Python 3.12及支持WebGL的浏览器。在仓库根目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-integration.txt
npm.cmd ci
.\.venv\Scripts\python.exe scripts/prepare_data.py
.\.venv\Scripts\python.exe scripts/start_integrated.py
```

打开 `http://127.0.0.1:5173/`。以后双击“启动装备建模平台.cmd”即可。关闭终端或按Ctrl+C停止服务。本机桌面快捷方式继续使用已配置的本地Python环境，不需重新安装。

服务使用5173（页面）和8765（Python）。修改城市生成数据后需重启Python服务并刷新页面。仅运行 `npm run dev` 不会启动Python。`dist/`静态站点也必须配置 `/api/capabilities` 反向代理和Python服务才能评估光电／声学；启动方式见 `scripts/start_integrated.py` 与 `vite.config.js`。

## 导出与兼容

- “导出参数与计算报告”保留设备方案格式，并增加 `capabilityAssessment`（Python资料评估）与 `assessmentMode`。默认模式的 `results` 只包含JavaScript模型结果，两个数组合计对应所有设备。
- 设备工作设置保存在 `devices[*].capability`，目标宽高与频带在 `target.capability`。导入时验证设置并按当前网格重新计算；不信任导入的旧结果。
- 场景对比JSON包含各场景的输入、设备配置、配置哈希、结果及来源状态。快照与之后的编辑隔离。
- 中文HTML仅包含可用指标和简洁中文说明，不包含开发注释或展开的原始JSON。
- 原 `student-capabilities-1` 后端接口版本保持兼容，单次支持1～64个光电／声学设备。原Python独立演示仍可运行。
