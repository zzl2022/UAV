## 1. 先用一句话讲清楚这个模块

**推演优化模块要解决的是：在真实城市建筑和地形上，从若干装备型号、建筑或地面安装点和姿态中，自动挑出成本可接受、覆盖尽量完整、施工相对方便且电磁冲突可控的部署组合，再用盲区和动态入侵场景检验它。**

它不是简单地“多放设备”，也不是在地图上画几个圆。其核心是一条可复核的计算链：

```text
真实场景与装备参数
        ↓
生成空域采样点、真实候选点位和设备姿态
        ↓
逐候选 × 逐采样点 × 逐工况做真实感知判定
        ↓
形成覆盖矩阵
        ↓
加权贪心选点 → 删除冗余 → 再补选 → 二重覆盖增强（核心点权重更高）
        ↓
雷达换频 / 局部移位 → 按最终设备状态重算覆盖
        ↓
四指标归一化评分 + EMC 降权，得到推荐方案
        ↓
盲区归因 + 三类动态威胁验证 + 报告与过程数据导出
```

可以把它理解为三步：

1. **先算清楚每台设备到底能看住哪些地方；**
2. **再用尽量少的设备组合看住尽量重要的地方；**
3. **最后主动找问题：哪里仍是盲区、遇到蜂群是否超载、设备之间是否互相干扰。**

## 2. 设计目标与核心问题

### 2.1 设计目标

模块同时追求五个目标：

| 目标 | 在算法中的体现 |
| --- | --- |
| 覆盖有效 | 使用真实建筑/地形遮挡和装备感知模型，不以标称半径代替有效覆盖 |
| 资源受控 | 每套方案都有相对预算和设备数量上限 |
| 多工况稳健 | 同时考察基线、无线电静默、雨雾噪声、电磁干扰四种工况 |
| 方案可比较 | 将覆盖、盲区、成本、施工可行性统一归一化评分 |
| 结果可解释 | 保存每次选点、删点、补选、换频、移位、覆盖贡献和冲突清单 |

### 2.2 需要解决的四个核心矛盾

1. **覆盖与成本的矛盾**：设备越多通常覆盖越好，但预算和数量不可能无限增加。
2. **标称能力与实际环境的矛盾**：设备参数写着“探测 8 km”，不代表隔着楼仍能探测 8 km。
3. **单工况最好与多工况稳健的矛盾**：依赖无线电侦测的方案，在目标静默时可能明显退化。
4. **覆盖提升与设备互扰的矛盾**：雷达加密部署可能补了覆盖，却引入同频、邻频或共址问题。

### 2.3 算法定位

这是一个**带多工况复核和工程约束的加权集合覆盖启发式算法**，不是数学全局最优求解器，也不是实测装备验收系统。

它回答的是：

> “在当前场景、当前模型、当前采样和当前约束下，哪套候选组合更值得推荐，依据是什么，还有什么残余问题？”

它不回答：

> “现实连续空域绝对无盲区”“该组合是数学全局最优”“实际装备一定有某个探测概率”。

## 3. 理解算法所需的四个基础概念

### 3.1 空域采样点：把连续空间变成可计算的检查点

城市低空空域是连续的，计算机无法逐点检查无限多个位置，因此模块先选取有代表性的采样点。

默认设置是：

- 范围：核心建筑周边约 **2.4 km × 2.4 km**；
- 水平网格：默认 **500 m**，允许输入 **50～1000 m**；50 m 为精细网格，受 50,000 个采样位置和 200 万候选×采样组合上限约束。
- 离地高度：默认 **30 / 60 / 100 m**；
- 额外检查：在核心区较高建筑附近加入近立面采样点；
- 核心区：默认以核心建筑为中心、半径 **700 m**。

**类比：**这类似于验收照明系统时，不可能检查每一寸地面，而是先选一批代表性位置测照度。测点全部合格，说明这些测点合格，但不能直接证明任意位置都合格。

### 3.2 候选设备：点位、型号和姿态共同构成一个候选项

一个候选不只是“某栋楼”，而是：

```text
一个真实安装表面 + 一个装备型号 + 一套参数 + 一个安装姿态
```

例如，同一屋顶上的 03D 雷达，会分别形成俯仰角 `0° / −15° / −30°` 三个候选。它们的覆盖能力可能不同，优化器可以只选其中一个。

### 3.3 覆盖矩阵：把物理判定转成优化器能处理的数据

若共有：

- `K` 个候选设备；
- `N` 个有效空域采样点；
- `4` 种工况；

则每个候选都会得到一张覆盖表，记录它在每种工况下能覆盖哪些采样点。

代码中把二维下标 `(工况 c, 采样点 j)` 展平为：

```text
index = c × N + j
```

因此，后续优化不再需要反复计算物理公式，只需在这张矩阵上比较“新增覆盖收益”。

### 3.4 模型裕量：不是探测概率

感知模型会输出 `marginDb`，可通俗理解为：

> 在当前距离、视场、遮挡、目标特征和环境损耗下，信号或有效像素距离判定门限还有多少余量。

- `marginDb < 0`：未达到模型门限；
- `marginDb ≥ 0`：达到原始模型门限；
- 规划覆盖默认进一步要求 `marginDb ≥ 3 dB`：额外保留工程余量。

**必须强调：裕量不是实测探测概率，3 dB 预留也不是厂家认证指标。**

## 4. 输入与输出定义

### 4.1 主要输入

| 输入类别 | 关键内容 | 默认值或约束 |
| --- | --- | --- |
| 城市场景 | 建筑轮廓、高度、地面高程、三维表面查询、坐标原点、源数据哈希 | 必须能定位当前场景核心建筑 |
| 装备选择 | 装备建模中已选型号及其已保存参数 | 至少一款；从七款预设中选择可用项 |
| 推演范围 | `core` 默认核心范围，或自定义宽度、深度 | 默认 2400 m × 2400 m |
| 采样设置 | 网格间距、高度层 | 网格 50～1000 m；代码支持 1～5 个 10～500 m 高度层，界面固定 30/60/100 m |
| 资源约束 | 总预算、设备上限、候选点上限 | 默认预算 600、设备上限 64、候选点设置 192 |
| 相对成本 | 雷达、无线电、光电、声学 | 默认 12 / 5 / 4 / 2，均为相对单位 |
| 核心权重 | 核心区半径、核心采样权重 | 默认 700 m、3 倍 |
| 覆盖门限 | 规划预留裕量 | 默认 3 dB |
| 目标特征 | RCS、尺寸、发射频率、EIRP、声压、热对比、速度等 | 来自当前场景目标快照 |
| 环境参数 | 雨、能见度、照度、电磁噪声、交通噪声、温度、风等 | 来自当前场景环境快照 |
| 评分权重 | 覆盖、盲区、成本、施工可行性 | 默认 0.40 / 0.25 / 0.20 / 0.15，必须非负且和为 1 |
| 威胁配置 | 数量、方向、方位角、离地高度、速度 | 数量 1～128，方向 1～16，速度不超过 100 m/s |
| 方案类型 | 经济型、均衡型、增强型 | 至少选择一套 |

七款装备预设为：02C 雷达、03D 雷达、TDOA-X1B、OA-X1Bmini、X1C、NVT-951 光电和 CRY8500 声学。当前界面从“装备建模已选型号”读取选择，并应用对应已保存参数，不再要求在推演页重复选择。

### 4.2 四种覆盖工况

| 工况 | 目标状态与环境变化 | 主要检验目的 |
| --- | --- | --- |
| `nominal` 基线·发射 | 目标正常发射，沿用当前环境 | 检查基础覆盖 |
| `silent` 无线电静默 | 目标 `emitting=false` | 检查是否过度依赖无线电侦测 |
| `weather` 雨雾及街道噪声 | 降雨 30 mm/h、能见度 0.3 km、雨噪 55 dB、交通噪声 65 dB | 检查传播和声学性能退化 |
| `interference` 电磁干扰 | 电磁底噪 +10 dB、同频干扰 +10 dB、串扰 +5 dB | 检查干扰条件下的覆盖韧性 |

这些是有限的代表性扰动，不代表已经遍历所有真实天气和攻击条件。

### 4.3 主要输出

流水线返回两个对象：

#### A. `report`：完整推演报告

主要字段包括：

- `settings / weights / environment / target`：本轮完整输入快照；
- `scope / sampling`：请求范围、有效范围、采样点和排除项；
- `plans`：各方案的设备、点位、成本、覆盖矩阵、指标和优化轨迹；
- `comparison / scoring / recommendedId`：评分、排名和推荐方案；
- `blindspots`：每套方案、每种工况的盲点及几何归因；
- `threatsByPlan`：每套方案的三类威胁结果；
- `threats`：推荐方案的威胁结果，供既有界面使用；
- `emc`：冲突、附加损耗、结论及自动处置记录；
- `deploymentStatus`：`deployable` 或 `unresolved`；
- `limitations`：结果适用范围和不能外推的内容。

覆盖矩阵中的每个整数表示：

```text
0 = 无设备覆盖该采样点
1 = 恰好一台设备覆盖
>1 = 多台设备冗余覆盖
```

因此它不仅能算覆盖率，还能算核心区的二重覆盖率和单设备独立贡献。

#### B. `run`：可归档的过程数据

采用 `task3-run/1.0` 结构，保存本轮设置、方案摘要、盲区、威胁、EMC、规则提炼输入和数据来源，供多轮统计及复核使用。

## 5. 核心算法逐步拆解

## 5.1 第一步：生成有效空域采样

### 规则网格

在每个网格中心、每个指定离地高度生成候选采样点：

```text
采样高度 y = 该位置 DEM 地面高程 + 离地高度 AGL
```

随后执行两项排除：

1. `groundAt(x,z)` 无数据：记为 `outsideDem`，不进入有效样本；
2. 采样高度不高于建筑/地形表面上方 1 m：认为处于实体内部或过贴近表面，记为 `insideBuildings`，不进入有效样本。

这些排除项不会被算作“已覆盖”，也不会被偷偷计入覆盖率分母。

### 近立面补充采样

为避免规则网格漏掉核心建筑附近的关键空间，算法会：

1. 找出核心半径内较高的最多 24 栋建筑；
2. 在每栋建筑外环的两个代表顶点沿径向外移约 12 m；
3. 在最低高度层加入近立面点；
4. 同样执行 DEM、实体内部和去重检查。

### 自定义范围的边界处理

自定义范围会先与 DEM 有效边界求交集：

- 有交集：只计算有效区域，并记录裁切；
- 完全无交集：直接报错，不进行无依据外推；
- 请求范围内仍有 DEM 空洞：逐点排除并记录。

## 5.2 第二步：给采样点分配优化权重

采样点权重由“区域重要性”和“工况重要性”共同决定：

```text
样本基础权重 = 核心区样本 3，外围样本 1
工况倍率     = 基线工况 2，其余工况 1
最终权重 w(c,j) = 样本基础权重 × 工况倍率
```

默认情况下：

| 样本位置 | 基线工况 | 静默/雨雾/干扰工况 |
| --- | ---: | ---: |
| 核心区 | 6 | 3 |
| 外围 | 2 | 1 |

这意味着优化器不是只追求“覆盖点数最多”，而是优先保证核心区和基线工况，同时仍保留其他工况的覆盖收益。

## 5.3 第三步：生成真实候选点位与设备变体

### 安装点位筛选

1. 建筑轮廓与推演范围相交后进入检查。用户勾选的连通建筑及其占地实施禁部署；核心标志用于定位和加权。
2. 屋面候选先尝试外环平均位置，再尝试带孔三角剖分所得三角形的内部点；在三维场景中核验命中的建筑 ID、表面高程与地形。
3. 外立面候选沿外墙检查建模高度的三分之一和三分之二两个支承标高。安装点须在外侧、支承点高于外侧表面，设备高度低于楼顶。实际楼层、支架与施工许可仍需核验。
4. 开放地面候选取有效区域站点网格单元中心，核验命中地面且不在禁部署占地内。候选只表示模型具备相应几何条件。
5. 建筑按站点网格分组，格内依核心距离排序，逐格轮取。屋面、立面和开放地面交替取点，某类不足时由其余类型补足。原有 140 m 楼高剔除与每格仅取最高、最低楼的规则已移除。
6. 总量受 `maxSites` 约束；超过 128 的预算中最多留 64 席给残余补点。几何校验通过后才占用席位。没有有效安装点时报告错误。

### 设备变体

- 雷达：每个已选雷达型号生成 `0° / −15° / −30°` 三种俯仰姿态；
- 其他设备：生成一个默认姿态；
- 光电和声学：朝向核心区；
- 装备参数：应用装备建模中保存的型号参数；
- 雷达载频：先按模型频道赋初值，方案选定后再统一优化分配。

### 候选成本

固定安装候选的相对成本为：

```text
installationProxy = 1 + (安装点实际离地高度 - 2 m) / 100 m
候选成本 = 该类型相对成本 + 0.2 × installationProxy
```

所以点位越高，安装代理成本略高。这里的成本只用于方案相对比较，**不是人民币报价**。

## 5.4 第四步：逐候选计算多工况覆盖矩阵

这是整个模块最耗时、也最关键的一步。

### 两级判定：先快判，再做真实遮挡查询

对每个“候选设备—采样点”组合：

1. **无遮挡快判**：先检查近距盲区、标称距离、方位视场和俯仰视场；
2. 若几何上必然不可达，直接跳过，不查询建筑；
3. 若可能可达，再调用 `query.trace(设备位置, 目标位置)`，检查建筑和地形遮挡、端点地面高程及路径数据完整性；
4. 分别在四种工况下调用子任务二的 `evaluate` 感知模型；
5. 只有满足以下条件才写入覆盖矩阵：

```text
status == "within-model"
且 marginDb 不为空
且 marginDb ≥ 规划预留门限（默认 3 dB）
```

`within-model` 要求几何、信号等判定有效；若路径数据不完整而得到 `uncertain`，不会被当成规划覆盖。

### 为什么这一步可靠且较快

- **可靠**：最终覆盖来自装备模型和真实几何，而不是圆形半径近似；
- **较快**：距离/视场快判减少射线查询，同一“站点—采样点”的几何上下文还会缓存复用；
- **可审计**：每个覆盖结论都能回到具体设备、目标、环境和遮挡上下文重新计算。

## 5.5 第五步：对候选池仍无法覆盖的位置进行邻近补点

即使已经生成初始安装候选，仍可能存在没有任何候选能覆盖的点。此时算法不会降低门限，而是搜索新点位。

### 补点顺序

- 优先核心区；
- 同一区域内优先低高度层；
- 同一水平位置的多个未覆盖样本只设一个补点锚点。

### 搜索方法

1. 优先使用 03D 雷达；若未选择，则使用当前已选的第一款雷达；没有雷达则不执行这一补点步骤；
2. 以盲点为中心，分别搜索 **80 / 180 / 350 m** 三个半径；
3. 每圈检查 **12 个方向**；
4. 候选必须有真实地表面，设备放在表面上方 2 m；
5. 指向盲点计算姿态，俯仰角限制在 **−60°～0°**；
6. 要求到锚点路径已知且无遮挡；
7. 要求该补点对锚点在**全部四种工况**下都达到 3 dB 规划门限；
8. 成功后，再计算该补点对全部采样点的覆盖贡献，加入候选池。

补点数量上限为：

```text
min(64, maxSites − 原站点数)
```

若仍找不到合格补点，盲点会保留，而不是被标记为“已解决”。

## 5.6 第六步：用加权贪心集合覆盖生成初始方案

### 每一步选什么

对于尚未选择的候选 `i`，计算：

```text
新增收益 Gain(i) = 所有“该候选能覆盖、且当前尚未覆盖”的矩阵项权重之和
性价比 Score(i) = Gain(i) / 候选成本
```

在满足以下约束的候选中，选择 `Score` 最大者：

```text
累计成本 + 候选成本 ≤ 当前方案预算
当前设备数 < 当前方案设备上限
```

若新增收益为 0，该候选在这一阶段不会被选中。

### 一个可手算的教学示例

> 以下仅用于解释算法，不是项目仿真结果。

假设当前有三个未覆盖事件，权重分别为 A=6、B=3、C=2：

| 候选 | 覆盖 | 成本 | 当前新增收益 | 收益/成本 |
| --- | --- | ---: | ---: | ---: |
| 设备 1 | A、B | 5 | 9 | 1.8 |
| 设备 2 | A | 4 | 6 | 1.5 |
| 设备 3 | B、C | 2 | 5 | 2.5 |

第一轮选设备 3，因为它的边际性价比最高，而不是因为它的总覆盖数最多。

第二轮中，B 已覆盖：

- 设备 1 的新增收益只剩 A=6，性价比为 `6/5=1.2`；
- 设备 2 的性价比仍为 `6/4=1.5`。

因此第二轮选设备 2，最终成本 6，三个事件都被覆盖。

这个例子体现了贪心的核心：**每一步都看“现在还能增加多少”，而不是看设备原本总共能覆盖多少。**

### 冗余删除与再补选

初始选择结束后，算法反向检查已选设备：

> 如果某台设备覆盖的每一个矩阵项，在删除它之后仍至少由另一台已选设备覆盖，则删除该设备。

删除不会降低当前覆盖集合，却能释放预算和数量名额。随后再次执行贪心补选，最多进行 **4 轮“选择—反删—补选”**。

它解决的是：早期选中的设备，可能被后续更优组合变成冗余；如果不在结尾清理，就会浪费预算。

## 5.7 第七步：形成三套差异化策略

| 方案 | 可用装备 | 预算 | 设备上限 | 额外目标 |
| --- | --- | ---: | ---: | --- |
| 经济型 | 优先只使用已选的雷达和无线电；若完全没有这两类才使用全部已选装备 | 50% | 50% | 控制成本 |
| 均衡型 | 全部已选装备 | 75% | 75% | 覆盖、类型与成本折中 |
| 增强型 | 全部已选装备 | 100% | 100% | 饱和后增加二重覆盖，核心点权重更高 |

预算和设备数按比例后会四舍五入，设备数至少为 1。

### 增强型的二重覆盖机制

增强型先运行普通贪心。之后继续选点时：

- 尚未覆盖的事件：增益系数仍为 `1`；
- 已有一重覆盖的事件：增益系数为 `0.5`；
- 已有两重及以上覆盖：不再产生增益。

即：

```text
增益 = 未覆盖权重 + 0.5 × 仅一重覆盖的权重
候选得分 = 增益 / 成本
```

因此增强型不是简单“把设备翻倍”，而是在预算允许时，以半价边际收益换取冗余。

**实现细节：**文档常把这一策略简称为“核心双覆盖”，但当前代码的二重覆盖增益实际上作用于全部采样点，并未限定为核心区；核心采样点只是因为权重更高而通常优先。评分阶段的额外奖励则只取基线工况的核心区二重覆盖率，两处口径不能混淆。

## 5.8 第八步：EMC 处置后重新计算最终覆盖

方案初步生成后，不能直接把候选矩阵相加就结束，因为载频和位置还可能变化。

实际顺序为：

1. 对所选雷达进行频道分配；
2. 检查五类 EMC 冲突；
3. 若存在 `fail`，先尝试换频，再尝试局部移位；
4. 对载频或位置发生变化的设备重新计算覆盖；
5. 对有同频附加损耗的设备重新验证相关采样点；
6. 得到最终覆盖矩阵和独立覆盖贡献。

### 初始频道分配

雷达按型号分组，逐台从合法模型频道中选择冲突代价最小的频道：

```text
频道代价 = 10 × 已分配的近距同频冲突数 + 已分配的近距邻频冲突数
```

同频代价权重更高，因此优先避免 `fail`，再减少 `warning`。并列时选择频道列表中靠前者，保证结果确定。

模型频道为：

- 02C：9.30 / 9.45 / 9.60 / 9.75 GHz；
- 03D：16.0 / 16.5 / 17.0 / 17.5 GHz。

这些是推演模型的离散频道假设，不代表厂家实际可用频点。

### 残余严重冲突的自动处置

每一步只接受能减少 `fail` 数的动作：

1. **优先换频**：仅处理当前严重冲突涉及的设备，只使用既有合法模型频道；
2. **无法继续换频时局部移位**：在原有点位 1200 m 内，从既有真实候选点中寻找同型号、同俯仰姿态替代点，最多检查 24 个；超过上限时按距离分位取样，覆盖近端和远端；
3. 选项按以下顺序比较：严重冲突更少、提示更少、估算覆盖损失更小、移动距离更短、键值顺序；
4. 使用设备状态签名防止反复回到旧状态；
5. 默认最多 `min(64, max(8, 2 × 设备数))` 步。

如果合法换频和局部移位仍不能清除严重冲突，则保留 `unresolved`，明确提示需要人工调整，不宣称方案可部署。

**预算边界：**预算和设备上限严格作用于初始贪心及冗余增强。EMC 局部移位保持设备数不变，并按替换后的候选组合复核方案预算；最终成本取实际入选候选成本之和。

### 为什么必须重算覆盖

换频可能影响传播计算，移位更会改变距离、视场和遮挡。因此最终报告使用的是**处置后的真实设备状态**，不是处置前的旧覆盖结果。

最终还逐台统计：

- `coveredSamples`：该设备总共覆盖多少点；
- `independentSamples`：若去掉其他设备，只有该设备能覆盖多少点。

后者能直观识别“看起来设备很多，但真正不可替代的设备有多少”。

## 5.9 第九步：四指标归一化评分与 EMC 回写

### 指标一：覆盖完整性

先取四种工况中的最低覆盖率：

```text
coverageRaw = min(四种工况 coverageRate)
```

再加入基线工况的核心区二重覆盖奖励：

```text
coverage = min(1, coverageRaw + 0.15 × coreRedundantRate)
```

其中 `coreRedundantRate` 是核心区中“至少两台设备覆盖”的采样点比例。

因此，界面中的“覆盖完整性”并不总是等于最弱工况覆盖率；报告同时保留 `coverageRaw` 和 `coverageMean`，避免混淆。

### 指标二：盲区占比

```text
blindRatio = 四种工况 blindRate 的平均值
blindRate = 未覆盖采样数 / 有效采样数
```

尽管界面名称为“盲区面积占比”，当前评分实际使用的是**采样点比例**。报告另提供按网格中心外推的单高度层近似面积，两者不能混为一谈。

### 指标三：相对成本

使用最终所选候选的实际成本之和，越小越好，单位不是人民币。

### 指标四：施工可行性代理

单台设备的代理分由四部分组成：

```text
mass   = clamp(1 − 重量 / 85)
volume = clamp(1 − 体积 / 0.31)；文档缺尺寸时取 0.9
mount  = 固定式或多模架设 1.0；车载式/固定式 0.85；未知 0.7
height = clamp(1 − 0.15 × 安装点离地高度 / 100)

单台得分 = 0.40 × mass + 0.25 × volume + 0.15 × mount + 0.20 × height
方案得分 = 所有设备得分的平均值；空方案为 0
```

所有分项限制在 `[0,1]`。屋顶承重、产权、供电和网络没有实测数据，因此该指标只是相对代理。

### 跨方案 min-max 归一化

对当前参与比较的方案：

```text
正向指标归一化 = (x − min) / (max − min)
反向指标归一化 = (max − x) / (max − min)
```

覆盖和施工可行性为正向；盲区和成本为反向。

若某指标在所有方案中完全相同，或只生成了一套方案，则该指标归一化值直接取 1。

基础综合分：

```text
scoreRaw = 0.40 × 覆盖归一值
         + 0.25 × 盲区归一值
         + 0.20 × 成本归一值
         + 0.15 × 施工归一值
```

权重可由用户修改，但必须四项齐全、非负且总和为 1。

**讲解时要说明：这是当前候选集合内的相对评分，不是跨场景绝对分数。增加或删除一套方案，min-max 范围可能变化，其他方案的归一化分也可能随之变化。**

### EMC 降权与最终推荐

```text
若 fail 数 f > 0：emcFactor = max(0.70, 0.85^f)
否则若存在 warning：emcFactor = 0.97
否则：emcFactor = 1

最终得分 score = scoreRaw × emcFactor
```

最终排序优先级：

1. 无 `fail` 的方案优先；
2. 再比较 EMC 回写后的得分；
3. 得分相同则相对成本较低者优先。

若所有方案都仍有 `fail`，仍可给出相对排序，但 `deploymentStatus=unresolved`，不会把第一名标成“可部署最优”。

## 6. EMC 五类规则：它到底检查什么

EMC 对方案内所有无序设备对计算**三维距离**，检查以下规则：

| 类型 | 触发条件 | 级别 | 对覆盖的影响 |
| --- | --- | --- | --- |
| 同频 `co-channel` | 两台发射设备频差 <0.1 GHz，且距离 <600 m | `fail` | 双方增加同频附加损耗并重验覆盖 |
| 邻频 `adjacent-channel` | 频差处于 [0.1, 0.5) GHz，且距离 <300 m | `warning` | 不直接增加覆盖损耗 |
| 发射落入接收频段 `receiver-overlap` | 发射频点落入接收范围或离散频点 ±0.02 GHz，且距离 <600 m | `fail` | 记录冲突并进入处置 |
| 前端阻塞 `frontend-block` | 发射功率 ≥1000 W，距无线电接收机 <50 m | `warning` | 给出拉距建议 |
| 同点位过密 `co-site` | 距离 <10 m，且至少一方有射频发射 | `warning` | 建议错开至少 10 m |

同频设备对的附加损耗为：

```text
penaltyDb = 6 × (1 − 三维距离 / 600)
```

该损耗分别累加到两台设备，并在最终覆盖复核时加入环境的 `cochannelDb`。同一设备对只罚一次。

光电和声学自身没有射频发射与接收，因此不会产生自身射频互扰；但若与有源射频设备共址，仍可能收到共址提示。

这些规则是工程代理，不是频谱合规认证。其意义是提前暴露明显的频率与空间布置问题，而不是替代电磁兼容实测。

## 7. 盲区归因：从“哪里没覆盖”进一步解释“为什么没有覆盖”

算法只对最终覆盖矩阵中计数为 0 的样本进行归因，每个盲点只归入一个类别，优先级为：

```text
楼栋夹缝 > 建筑背面阴影 > 低空贴楼 > 围墙边角 > 其他
```

| 类别 | 主要几何判据 | 输出成因 |
| --- | --- | --- |
| 楼栋夹缝 `gap` | 两栋近似对向建筑的方向夹角 >120°；到两楼的平面距离之和 ≤60 m；两楼屋顶均高于采样点 | 缝宽、建筑 ID、离地高度 |
| 建筑背面阴影 `shadow` | 所有几何上本可覆盖的设备都被建筑/地形截断，且遮挡物距盲点 ≤120 m | 遮挡距离、涉及设备数 |
| 低空贴楼 `lowFacade` | 离地高度 ≤45 m，且距最近建筑外环 ≤20 m | 立面距离、离地高度、建筑 ID |
| 围墙边角 `corner` | 距最近建筑外环顶点 ≤25 m | 角点距离、建筑 ID |
| 其他 `other` | 不满足以上几何特征 | 明确标记未满足四类特征 |

为避免对每个盲点遍历全城建筑，实现使用 **100 m 网格空间索引**，只搜索由近及远的网格桶，并用“质心距离−建筑外接半径”做预过滤。

### 讲解边界

- 盲区类别是**几何归因初值**，不是唯一物理原因；
- “围墙边角”当前实际依据的是建筑外环顶点，并未使用独立围墙矢量数据；
- 一个点同时满足多类时，只按上述优先级记录一类；
- 阈值适用于当前模型和采样口径，迁移场景应重新校订。

## 8. 三类威胁推演：静态覆盖之后，再检查动态检出与容量

## 8.1 默认威胁场景

| 场景 | 默认目标数与方向 | 时间组织 | 高度与速度 |
| --- | --- | --- | --- |
| 单机单点入侵 | 1 个方位，1 架 | 单条航线推演 | 30 m，15 m/s |
| 多方向同步入侵 | 4 个方向，各 1 架 | 同一时间轴同步推演 | 45/60 m，15 m/s |
| 蜂群饱和攻击 | 3 个方向，每个方向 14 架，共 42 架 | 同步推演，方向内错峰 | 30/45/60 m，12 m/s |

单机单点入侵固定为一架目标、一个来向和一个离地高度，可调整该来向、高度和速度；自定义轨迹仍是一架目标的一条折线航路。蜂群同方向目标沿同一来向穿越核心，并按架次增加 2 秒起飞延迟。历史报告中的八方位独立试飞记录保留原批次含义，不作为当前单机场景默认值。

## 8.2 航路生成

自动航路按配置的来向方位角，从距部署矩形范围最短水平距离 1000 m 的位置直线飞向核心，穿过核心后继续至起点关于核心的水平对称位置。来向角表示核心指向起点的方位（北为 0°，顺时针）。斜向、非正方形范围也采用相同距离口径。起点受有效地形地图边界限制；当外扩不足 1000 m 或部署范围触及地图边界时，从该方向地图边界起飞。对侧地图不足时，终点截在对侧边界。手绘轨迹保留原始路点及起终点，不应用自动外扩与对称延伸。

底部仿真场景与威胁参数表双向同步。仿真使用当前方案已计算的威胁帧，数量、方位、高度及物理速度均取该轮参数；修改输入后停止旧播放并禁用进度条，须重新生成方案后播放。底部倍速只改变播放快慢，不改变物理速度。

1. 水平路径按约 20 m 分段；
2. 每个点高度取：

```text
max(地面高程 + 设置 AGL, 建筑/地形表面高程 + 25 m)
```

3. 无 DEM 的点跳过；若一条航线不足两个有效点则报错；
4. 通过前后坡度包络限制高度变化，相邻水平距离 `d` 对应的最大下降尺度为 `d/3`；
5. 对被建筑阻挡的航段进行最多 3 轮抬升修复；
6. 最后记录仍可能存在的 `blockedSegments`，不把它伪称为真实可飞航路。

这是运动学演示路径，不包含真实飞控、动力学、空域许可和导航安全保证。

## 8.3 每 2 秒做一次真实检出判定

对每个在场目标、每台设备：

1. 根据时间对三维航路做弧长时间插值；
2. 先进行距离、视场、静默和频段快判；
3. 必要时查询真实几何遮挡；
4. 调用感知模型，要求 `status=within-model` 且 `eligible=true`；
5. 同频附加损耗加入该设备的环境干扰项。

**这里不额外要求规划的 3 dB 预留。**也就是说：

- 静态规划：默认 `marginDb ≥ 3 dB`，用于保守选点；
- 动态推演：达到感知模型原始门限即可检出，用于观察运行状态。

## 8.4 并发容量截取

同一帧内，如果一台设备可检出多个目标：

1. 按目标 `marginDb` 从高到低排序；
2. 只保留设备 `capacity` 允许的前若干个；
3. 超出部分记录为 `overflow`；
4. 某台设备溢出不代表目标一定完全漏探，其他设备仍可能检出它。

输出包括：

- 首次检出时间，以各目标自己的起飞时刻为基准；
- 活跃帧中的检出占比；
- 全部在场目标同帧均被检出的帧数；
- 容量溢出架次及涉及目标数；
- 连续两帧未检出后的失联事件。

平均首报时间只对“曾经检出过”的目标求平均，从未检出的目标不会被当成 0 秒首报。

## 9. 可选扩展：警车移动雷达补盲

该功能是在当前方案上做增量修复，**不会重跑整套候选生成、方案评分和威胁流水线**。

### 执行逻辑

1. 读取当前方案、当前工况的盲点，核心盲点优先，最多取 12 个锚点；
2. 优先复用 03D，否则使用已选的第一款雷达；无雷达则保留原方案；
3. 在盲点周围按 500 / 750 / 1000 m 圆环、12 个方向搜索，粗候选最多 144 个；
4. 只接受 `surface≈ground` 的开阔地表，容差 0.5 m，不把屋顶当道路；
5. 挂载高度设为地面以上 2 m；
6. 粗搜索无法继续减盲时，对剩余锚点进行 750 m 半径、25 m 步长细网格搜索；
7. 每次选择能覆盖最多剩余盲点的候选，直到当前工况无可继续减盲的候选；日常部署再按可用车辆数做组合复核；
8. 对每台候选依次尝试合法频道，不允许引入新的 `fail`，也不允许方案总 `fail` 数增加；
9. 加入后对原方案与新增设备的所有采样点、所有工况全部重算；
10. 若发现原已覆盖点发生回退，或新增设备引入严重 EMC 冲突，则停止生成派生方案。

新增成本按每台“雷达相对成本 + 0.2”计算。输出明确区分：

- `covered`：当前工况原盲点已全部覆盖；
- `partial`：只减少了一部分盲点；
- `no-candidate / emc-unavailable / no-radar / no-blindspots`：说明未部署原因。

取消或切换方案时可恢复快照，避免重复叠加移动设备。

### 必须同时说明的限制

- 当前没有完整道路网，候选只是开阔地表几何代理；
- 未验证道路可达、停车条件和施工条件；
- 原方案比较排名不会因移动补盲自动重算；
- 警车只改变部署方式，不改变装备文档中的雷达射频能力。

### 日常部署估算

警车补盲结果会把每个盲点对各新增驻点的可见关系压缩为覆盖分组。用户输入可用警车数量后，后台用 HiGHS 求解“在车辆数上限内最多覆盖多少原有盲点”；输出使用车辆数、补足点数和剩余盲点。该估算只复用本轮已复核的驻点组合，不重新生成候选，也不改变原方案排名。

### 通用布设规则

页面读取跨地图规则库 `public/data/cross-map-deployment-rules.json`，按当前地图、输入、方案和本轮设备逐条核对触发条件。规则包含支持/反例地图、来源运行编号和原始记录路径；未提供可比基线或输入已变化时，不把历史结论强行关联到本轮设备。

### 报告与 PDF

完整版 PDF 包含三套方案、覆盖分档图、威胁、EMC 初检与处置、警车部署与通用规则核验；精简版只导出当前方案。导出前会复核方案与工况未变化，PDF 中的关联设备、覆盖分档和规则结论均来自同一轮报告。

## 10. 实际执行顺序与界面阶段的关系

流水线展示五个阶段；界面另提供通用布设规则、警车部署和完整/精简 PDF：

```text
候选方案生成 → 覆盖推演 → 多指标择优 → 威胁场景验证 → 电磁兼容校核
```

为了得到正确结果，代码内部的依赖顺序更细：

1. 输入校验和请求快照；
2. 采样与候选生成；
3. 候选覆盖矩阵和残余盲点补点；
4. 三套策略选点；
5. 每套方案执行频道分配、EMC 自动处置和最终覆盖重算；
6. 盲区分类；
7. 四指标基础评分，EMC 回写并确定推荐；
8. 对每套方案执行三类威胁推演；
9. 汇总 EMC 完成状态，生成 `report` 和 `run`。

因此，**EMC 并不是只在最后出一份独立报告，而是在推荐之前就已经参与覆盖修正和方案排序。**最后一个 EMC 阶段信号主要用于完成界面流程。

## 11. 核心创新点与优化策略

以下更准确地说是**工程组合创新**，不是提出了新的集合覆盖理论。

### 11.1 多工况统一覆盖矩阵

同一候选同时面对四种工况，优化目标直接包含核心区和基线权重，避免只在理想环境中选点，再做无关的事后解释。

### 11.2 “贪心—反删—补选”的预算回收

普通贪心一旦选点通常不再撤销。本实现允许删除已被后续组合完全替代的设备，再用释放的预算补选，减少早期决策造成的浪费。

### 11.3 不降低门限的盲点补点

补点必须位于真实表面、路径已知无遮挡，并对锚点通过全部四种工况的同一门限。找不到就如实保留盲点，避免为了指标好看而放松标准。

### 11.4 覆盖与 EMC 的闭环，而非两张皮

频道分配和局部移位会改变实际设备状态，因此算法重新计算受影响覆盖，再把同频损耗纳入最终覆盖验证。EMC 结论还会回写推荐分数，真正影响方案选择。

### 11.5 从“覆盖率”扩展到“冗余和不可替代性”

覆盖矩阵保留设备计数，可以分析核心区二重覆盖、设备总贡献和独立贡献，比单一覆盖率更能说明方案韧性。

### 11.6 蜂群容量不美化

动态推演不因为设备“几何上能看到”就无限接收目标，而是按帧、按设备、按裕量排序截取容量，并保留溢出和漏探统计。

### 11.7 计算效率优化

- 距离和视场快判，减少无效三维射线查询；
- 缓存站点—采样点的遮挡上下文；
- 候选站点、补点、移位和移动补盲均有明确上限；
- 使用建筑网格索引加速盲区归因；
- 在 Web Worker 中运行，定期让出事件循环并回报进度；
- 请求使用快照和递增 ID，新任务或取消会使旧结果失效，避免旧结果覆盖新参数；
- 参数变化后排队自动更新，已有结果在新结果完成前保留但标记为过期。

### 11.8 可解释与可追溯

每次选点保存增益、成本、性价比和累计覆盖；删除保存释放成本；EMC 保存动作前后状态；报告保存输入、坐标原点和源数据哈希。讲解时可以回答“为什么选它”，而不只是展示最终地图。

| 边界情况 | 实际处理 |
| --- | --- |
| 未选装备、未知预设 | 直接报错 |
| 权重缺项、负数、未知键或和不为 1 | 直接报错 |
| 场景缺少核心建筑定位 | 直接报错 |
| 自定义范围与 DEM 完全不相交 | 直接报错 |
| 没有有效空域采样点 | 直接报错 |
| 没有可用部署候选点 | 直接报错 |
| DEM 空洞或建筑内部采样 | 排除并计数，不外推、不记为覆盖 |
| 路径遮挡数据不完整 | 规划时不把 `uncertain` 当作有效覆盖 |
| 候选池仍有盲点 | 搜索邻近补点；找不到则保留 |
| 预算不足或没有新增收益 | 停止选点，不强行填满设备数 |
| 删除设备不降低覆盖 | 允许反删并释放预算，再补选 |
| 只生成一套方案或指标无差异 | 对应 min-max 归一化取 1，避免除零 |
| EMC 无严重冲突 | 不进入强制处置，提示级冲突仍保留 |
| EMC 严重冲突无法清除 | 标记 `unresolved`，需要人工调整 |
| EMC 移位后的安装代理成本变化 | 保留最终实际成本；当前未再次执行预算校验 |
| 同分方案 | 成本较低者优先 |
| 威胁航线全段无有效 DEM | 该航线生成报错 |
| 航段抬升后仍有阻挡 | 记录 `blockedSegments`，不宣称真实可飞 |
| 目标超过设备并发容量 | 按裕量截取并记录溢出 |
| 目标从未检出 | 首报为空，不纳入平均首报时间 |
| 移动补盲找不到合法点或频道 | 不新增设备，保留原盲点 |
| 移动补盲导致覆盖回退或新增严重冲突 | 中止派生方案生成 |

## 13. 结果解读时最容易说错的八句话

### 误区 1：“覆盖率 100%，所以整个区域没有盲区。”

正确说法：**当前有效采样点在当前模型和工况下全部覆盖，连续空域仍需更密采样或实测验证。**

### 误区 2：“盲区占比就是精确地理面积比例。”

正确说法：评分使用采样点比例；近似面积只按规则网格中心数 × 网格面积外推，不包含近立面点，也没有做边界和建筑多边形精确裁剪。

### 误区 3：“不同高度层的近似面积相加，就是地面盲区面积。”

正确说法：不同高度层是不同空域切片，不能直接相加称为地面面积。

### 误区 4：“裕量 10 dB 就等于很高的实测探测概率。”

正确说法：裕量是未标定模型输出，不是实测概率。

### 误区 5：“成本 152.5 就是 152.5 万元。”

正确说法：成本是相对单位，用于方案比较，不对应人民币报价。

### 误区 6：“EMC 通过就代表设备通过频谱认证。”

正确说法：这里只完成工程代理规则校核，不能替代认证和实测。

### 误区 7：“威胁场景中 42 架都被检出过，所以蜂群没有任何漏探。”

正确说法：“曾经检出”与“每帧都检出”不同，还必须看检出占比、同帧全检出数和容量溢出。

### 误区 8：“推荐方案就是数学全局最优。”

正确说法：它是当前候选集合和相对评分口径下的推荐解，没有全局最优证明。

## 15. 技术选型依据

### 15.1 为什么选择加权贪心，而不是默认引入精确求解器

加权集合覆盖本身属于复杂组合优化。项目选择贪心主要基于：

1. 浏览器内可运行，无需新增重型服务端；
2. 每一步增益、成本和约束都能展示，便于讲解和审计；
3. 适合与真实覆盖矩阵、预算、设备上限直接结合；
4. 通过反删补选、盲点补点和三套策略改善单纯贪心的短视问题。

代价是不能提供全局最优证明。HiGHS/OR-Tools 更适合后续做离线对拍或精确解增强。

### 15.2 为什么复用子任务二感知模型

如果部署模块另写一套“简化圆圈覆盖”，规划结果会与装备面板和动态飞行相互矛盾。复用 `evaluate + query.trace` 后：

- 静态规划与动态验证使用同一套装备语义；
- 建筑、地形、距离、视场、目标和环境能共同作用；
- 结果可回到同一模型复核。

代价是输出精度继承感知模型的未标定假设。

### 15.3 为什么使用 Web Worker

候选 × 采样 × 工况的计算量较大，放在主线程会阻塞地图交互。Worker 可让推演在后台执行，同时支持进度、取消、旧请求失效和保留上次完成结果。

### 15.4 为什么 EMC 使用规则代理

现有资料缺少完整天线方向图、调制方式、带宽、极化、发射时序和互扰标定数据，直接上认证级电磁仿真缺少可靠输入。因此先实现透明、可复核的同频/邻频/耦合/共址规则，并明确其非认证属性。

## 16. 可直接使用的口头讲解稿

### 16.1 约 1 分钟版本

> 第三个模块解决的是反无人机装备“放在哪里、放多少、怎样组合”的问题。它首先在真实建筑和 DEM 上生成空域采样点，再把模型核验的安装位置、装备型号和雷达姿态组合成候选。每个候选都要对四种工况逐点调用感知模型，并检查真实建筑遮挡，只有达到模型门限且保留 3 dB 裕量才算规划覆盖。然后算法按新增覆盖权重除以成本进行贪心选点，删除完全冗余的设备并再次补选，分别形成经济、均衡和增强方案。增强方案还会增加第二重覆盖，核心采样点因权重更高而通常优先。方案生成后，系统会优化雷达频道，必要时局部移位，并按最终状态重算覆盖。最后从覆盖、盲区、成本和施工代理四方面归一化评分，EMC 冲突会降权。系统还会解释盲区成因，并用单机、多方向和 42 架蜂群做逐帧验证，容量溢出会如实保留。所以它给出的不是一张理想化覆盖图，而是一套有依据、有残余问题清单的推荐方案。

### 16.2 约 3～5 分钟版本的组织顺序

1. **先讲问题**：设备多不等于覆盖好，标称距离不等于城市有效距离。
2. **再讲数据基础**：真实建筑/DEM、有效空域采样、屋面和外立面及地面候选。
3. **重点讲覆盖矩阵**：快判 + 遮挡 + 四工况感知实判 + 3 dB 预留。
4. **用手算例子讲贪心**：每一步按边际收益/成本，而非设备总能力。
5. **讲三个改进**：反删补选、残余盲点补点、增强型二重覆盖。
6. **讲 EMC 闭环**：换频/移位之后必须重算覆盖，EMC 还影响推荐。
7. **讲四指标评分**：最弱工况、核心冗余、相对成本、施工代理和 min-max。
8. **讲验证而非美化**：盲区归因、逐帧实判、容量溢出、未解决状态。
9. **最后讲边界**：离散采样、相对成本、代理 EMC、未标定模型、非全局最优。

## 17. 答辩常见问题与建议回答

### Q1：为什么不用穷举保证最优？

候选包含点位、型号和姿态，组合规模会迅速膨胀。当前目标是在浏览器内提供可解释、可交互的方案，因此采用贪心及多轮修复；精确求解器可作为后续对拍手段。

### Q2：为什么基线权重更高，会不会削弱其他工况？

基线权重为 2，但其他三种工况仍全部参与覆盖矩阵和收益计算；最终覆盖完整性又取四工况最低值，因此不是只看基线。核心冗余奖励也只是在最弱覆盖率之上有限加分，并封顶为 1。

### Q3：为什么无线电静默时覆盖会下降？

无线电设备依赖目标发射，静默时模型明确失效；雷达、光电和声学不依赖这一目标发射状态。算法保留这一差异，正是为了检验多类型冗余是否必要。

### Q4：贪心选完为什么还要删除设备？

后续设备可能共同替代早期设备的全部贡献。反删只删除“每个覆盖项都有其他设备兜底”的候选，所以不降低覆盖，还能释放预算用于补选。

### Q5：EMC 换频或移位后，原覆盖率还有效吗？

不能直接沿用。当前实现会对实际参数发生变化的设备重算覆盖，并对同频附加损耗逐点复核，报告使用最终状态结果。

### Q6：蜂群场景中“42 架均被检出”为什么仍有漏探？

这是“至少在某个时刻被检出”的统计。容量按每帧截取，某些帧会溢出；所以还必须结合检出占比、同帧全检出数和溢出架次判断。

### Q7：移动补盲后是否重新成为全局推荐方案？

不会自动重算原方案比较排名。移动补盲是当前方案的增量派生结果，会重算覆盖和 EMC，但报告明确保留原比较不变。

### Q8：加密网格是否一定得到同一个推荐方案？

不一定。采样点、覆盖矩阵、min-max 范围和候选修复路径都会变化。因此不同网格的结果应按各自轮次解释，不能直接混用分数。

## 19. 总结

这套算法的价值不在于宣称“绝对最优”或“绝对无盲区”，而在于把部署决策做成了一条**真实几何驱动、多工况联合、资源受约束、干扰可处置、结果可解释、残余问题不隐藏**的计算链。

最适合作为收尾的一句话是：

> **系统不是替我们掩盖部署中的不确定性，而是把覆盖依据、资源代价、方案差异和残余风险同时算清楚，让推荐结果能够被解释、被复核，也知道下一步应该补什么。**
