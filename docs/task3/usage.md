# 任务三 · 使用说明（优化部署与仿真推演）

> 本模块为《创意科目二：反无装备优化部署与仿真推演》子任务三交付物，集成于既有 Vite + Three.js 项目，不改动子任务一（三维建模）与子任务二（装备建模）功能。新增代码全部位于 `src/task3/`、`scripts/task3_report.js`、`tests/task3_*.test.js`；既有文件仅 `src/main.js` 末尾追加一行入口挂载。

## 1. 启动

```bash
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt   # 或 .venv/bin/python（macOS/Linux）
npm ci
.venv/Scripts/python scripts/prepare_data.py   # 等价 npm run prepare:data
npm run dev
```

浏览器打开开发服务器地址（默认 5173），点击顶部 **「任务三推演 →」**。

> 数据集（创意二数据集.zip）体积大不入库：建筑 SHP/DEM/影像/白模的获取方式见任务书发放渠道；放入 `创意二文件/创意二数据集/区域数据/` 后执行 `prepare_data.py` 即可。

## 2. 网页操作流程

1. **装备与推演输入**：先在“装备建模”中选择并保存型号，任务三只读该已选装备及其参数，不在推演页重复勾选。设置推演范围、网格间距、预算（相对成本单位，**非人民币报价**——文档未提供价格）、设备上限、四指标权重（覆盖完整性/盲区占比/成本/施工可行性，和为 1）。
2. **威胁参数**：分别设置单机单点（`single`）、多方向同步（`multi`）、蜂群饱和（`swarm`）的总数量、来向方位数与各方位角、离地高度列表和标称速度；字段含义与默认值见下节。
3. 点击 **「开始推演」**（参数自动更新时则等待最新一轮完成），流水线自动串联：候选方案生成 → 覆盖推演 → 多指标择优 → 威胁场景验证 → 电磁兼容校核；各阶段状态实时显示，可随时取消。取消后保留的是上一轮成功结果，不代表最新输入。
4. **方案对比**：三套差异化候选方案（经济型·雷达+无线电 / 均衡型·全类型 / 冗余增强型·全类型+核心双覆盖）按四指标归一化加权得分排序，★ 为推荐方案；EMC 冲突方案自动降权。
5. **盲区分布**：切换覆盖工况，三维场景按四类盲区着色（楼栋夹缝/围墙边角/低空贴楼/建筑背面阴影区/其他），图例可开关类别，点击列表条目定位到盲点并查看成因（缝宽、贴楼距离、遮挡距离等）。
6. **威胁回放**：推演完成后切换三类场景，播放/暂停/拖动进度；红色为已检出目标，连线为当前帧检出设备。场景下拉框只切换已完成结果的回放，修改数量、方位、高度或速度后必须取得新一轮推演结果；蜂群场景如实显示容量溢出与漏探统计。
7. **电磁兼容**：显示当前方案“通过/降额/不通过”结论与冲突清单（设备对、类型、距离、建议）。
8. **导出**：推演报告 JSON（完整方案/覆盖/盲区/威胁/EMC）与过程数据 JSON（布设规则提炼依据，schema `task3-run/1.0`）。两者均保存本轮实际使用的规范化威胁配置。

## 3. 威胁配置、坐标与可复现口径

### 3.1 配置字段与默认值

每个场景的规范化配置为 `{ count, directions, azimuthsDeg, aglM, speedMps, simultaneous }`，均为可 JSON 序列化的数值、数组和布尔值。`simultaneous` 是固定场景语义，不作为用户输入覆盖：`single=false`，`multi=true`，`swarm=true`。

| 场景 | 默认总数量 `count` | 默认来向 `azimuthsDeg` | 默认 AGL `aglM` / m | 默认速度 / (m/s) | 时间语义 |
| --- | ---: | --- | --- | ---: | --- |
| `single` | 8 | 8 个：0、45、90、135、180、225、270、315° | 30、60 | 15 | 各航路依次独立推演 |
| `multi` | 4 | 4 个：0、90、180、270° | 45、60 | 15 | 各目标同步推演 |
| `swarm` | 42 | 3 个：0、120、240° | 30、45、60 | 12 | 同步推演，方向内按 2 秒错峰 |

输入校验与分配规则：

- `count` 是 1–128 的整数；`directions` 是 1–16 的整数，且不得超过 `count`。
- `azimuthsDeg` 的长度必须等于 `directions`，每项都是 `[0,360)` 内的有限数值；方位角不做自动取模，360° 与负角会被拒绝。
- `aglM` 至少一项，每项为大于 0 且不超过 1000 m 的有限数值；`speedMps` 为大于 0 且不超过 100 m/s 的有限数值。
- 每个来向先分配 `floor(count/directions)` 架，余数从第一个来向开始依次各增加 1 架，因此总数始终严格等于 `count`。
- 以来向序号 `d`、方向内架次序号 `k`（均从 0 开始）取 `aglM[(d+k) % aglM.length]`，高度列表循环使用。
- 蜂群在每个来向内采用 `[0,+30,-30,+60,-60]` m 循环横向偏移，第 `k` 架延迟 `2k` 秒；single/multi 不加横向偏移或起飞延迟。

### 3.2 ENU 坐标、攻击来向与航向

本项目局部场景坐标采用 **X 向东、Y 向上、Z 向南**，所以**正北是 −Z**。攻击来向方位角 `θ` 以正北为 0°、顺时针增加：**北 0°、东 90°、南 180°、西 270°**。

设核心区中心水平坐标为 `(coreX,coreZ)`，目标从距中心水平半径 `r` 处来袭，则起点为：

```text
x = coreX + r sinθ
z = coreZ - r cosθ
```

因此 0° 表示目标从北侧向南入侵，90° 表示从东侧向西入侵。**来向不是飞行航向**：航向指向核心区，与来向相差 180°，即 `heading=(θ+180) mod 360`。默认径向航路从对应 bounds 边缘外 150 m 处飞向 core；蜂群横向偏移只改变同来向内的并列位置，不改变上述角度口径。

### 3.3 AGL、标称速度与复现

- `aglM` 是**相对局部地面的名义离地高度（AGL）**，不是海拔，也不是相对 core 的高度。初始航路高程取 `max(地面高程+AGL, 表面高程+25 m)`；随后还会执行坡度包络与建筑阻挡抬升，所以实际航路点高度可以高于配置的 AGL。
- `speedMps` 是**标称运动学速度**。航路时间按修复后三维航路的累计长度除以该速度计算，再加蜂群起飞延迟；不包含加速、转弯、风场或真实飞控动力学，也不应解释为实测地速。
- 同一城市/地形、装备、环境、目标与规范化威胁配置会确定性地生成相同航路和推演结果。实际配置保存在报告与过程数据的 `settings.threatConfigs`，并另存于各自的 `threats.<场景>.config`；复算时应使用这些已保存值，而不是依赖界面当前显示值。`runId`、创建时间和耗时等元数据不属于复现输入。

## 4. 命令行复算与多轮迭代

```bash
node scripts/task3_report.js           # 6 轮多配置迭代（基线/细网格/粗网格/低预算/高预算/低高度层）
node scripts/task3_report.js --quick   # 仅基线一轮，快速验证
```

输出：
- `artifacts/task3/runs/<runId>.json`：每轮完整过程数据（设置、候选统计、方案指标、四类盲区、威胁摘要、EMC 冲突），**布设规则的唯一数据来源**；
- `artifacts/task3/latest-report.json`：基线轮完整报告（含威胁逐帧）；
- 自动重新生成 `docs/task3/plans-comparison.md`、`threats-validation.md`、`emc-report.md`、`deployment-rules.md` 四份交付文档（数据全部来自当次真实仿真）。

## 7. 口径与局限（重要）

- 覆盖率为**离散采样点**口径（默认 500 m 网格 × 30/60/100 m 高度层 + 核心区近立面点），非连续空域无盲区证明。
- 成本为相对成本单位；施工可行性为重量/尺寸/架设方式/安装高度代理，屋顶承重/供电/网络未实测。
- EMC 为工程代理规则（同频/邻频/前端阻塞/共址），非频谱合规认证；选后换频（X 带 4×0.15、Ku 带 4×0.5 GHz 频道组）已自动执行，残余冲突如实列出。
- 威胁推演为运动学逐帧模型；检出全部来自子任务二感知模型对真实几何遮挡的实判，帧间漏检不排除。
- 雷达部署姿态（俯仰 0/−15/−30°、补点最低 −60°）与频道分组为模型假设，需厂家标定确认。
- 布设规则阈值适用于本场景与本采样密度；迁移他场景须用新轮次过程数据重新提炼。
- 输入方式：本期实现"选择不同类型装备 + 预算/网格/权重等自定义需求"分支（任务目标的"或者"分支）。"用户导入自定义白模（GLB）参与遮挡计算"未纳入本期——仓库原始白模高度语义未注明（README 明示），以其做部署决策依据不可靠；如需该能力，建议先标定白模垂直基准再接入 `createSceneQuery` 的建筑通道。
